# Figma handoff และแนวทางรีวิว

## ไฟล์และสถานะ

**[The Ranking — Public UI Sprint 01](https://www.figma.com/design/UADyUvdhR8AgxeurDdm5cu)** เป็นไฟล์แบบร่างที่แก้ไขเลเยอร์ได้ สำหรับปรับ UI ผู้ชม 3 หน้า ไม่ใช่รูปหน้าจอทั้งหน้าที่นำมาแปะใน frame

สถานะ ณ 25 ตุลาคม 2026:

- มีหน้า `01 — Desktop`, `02 — Mobile` และ `03 — Foundations & States`
- มีแบบหน้าแรก รายการทัวร์ และรายละเอียดทัวร์ทั้ง desktop/mobile รวม 6 frames
- มี local components และสี/spacing tokens สำหรับปุ่ม การ์ดผลแข่ง การ์ดทัวร์ และคู่แข่งใน bracket
- มี prototype links บางส่วน แต่ flow ยังต้องตรวจและเก็บรายละเอียด
- ฟอนต์กลางสำหรับ Body, Body small, Label, Strong, Section และ Title เปลี่ยนจาก IBM Plex Sans Thai Looped เป็น **IBM Plex Sans Thai** ผ่านหน้า Figma แล้ว คงน้ำหนักเดิม
- Display/Score ใช้ Barlow Condensed; การแก้ shared text styles ไม่ใช่หลักฐานว่าไม่มี detached หรือ overridden text ทุกจุด ต้องตรวจประกอบเมื่อรีวิว
- แบบยังไม่ผ่าน QA ครบทุกหน้าจอ จึงยังไม่ถือเป็น design ที่พร้อม implement โดยไม่มีการตัดสินใจเพิ่ม

ขณะสร้างแบบ การตรวจแก้รอบสุดท้ายติดโควตา Figma Starter MCP ต่อมาจึงเปลี่ยนฟอนต์ผ่าน Figma UI ได้หลังผู้ดูแลล็อกอิน ข้อจำกัดเครื่องมือเป็นสถานะของรอบทำงานนั้น ไม่ใช่สิ่งที่บอกว่าไฟล์ปัจจุบันแก้ต่อไม่ได้เสมอไป

## Brief ที่ใช้ตัดสินงาน

- ผู้ใช้หลักคือคนดูแข่งและสมาชิกชุมชนที่เปิดดูทัวร์ ผล และอันดับ โดยไม่ต้องล็อกอินเพื่ออ่านข้อมูลสาธารณะ
- เป้าหมาย flow คือ หน้าแรก → ค้นหารายการที่กำลังแข่ง → เปิดรายละเอียด → ดูสาย/ผล/ทีม และเข้าฟังก์ชันเดิมได้
- ภาพลักษณ์เป็น Esports dashboard ของ The Ranking / Overtime ใช้ดำ แดง ขาว ตัวเลขและสถานะแข่งขันอ่านง่าย
- ใช้ IBM Plex Sans Thai สำหรับเนื้อหาไทยและข้อความ UI ไม่ใช่รุ่น Looped
- งาน implement รอบแรกจำกัด 3 หน้า ใช้ bracket/form เดิม และไม่เพิ่ม business rules หรือ API ใหม่
- ชื่อทีม รายการ วันที่ ผล ตัวเลขสถิติ และ initials ในแบบเป็นข้อมูลสาธิต ไม่ใช่ผลแข่งหรือข้อมูลสมาชิกจริง

## ส่งอะไรให้รีวิว

สำหรับไฟล์เดิม ส่งแค่ frame ที่แก้หรือระบุว่าจะรีวิวทั้งชุดก็ได้ หากส่งไฟล์ใหม่ให้มีลิงก์ที่ผู้รีวิวเข้าถึงได้ โดยไม่ต้องเปลี่ยนเป็น public หากแชร์แบบจำกัดสิทธิ์ได้อยู่แล้ว

ข้อมูลขั้นต่ำ:

1. ลิงก์ file/frame และระบุ desktop/mobile ที่เกี่ยวข้อง
2. เป้าหมายของคนใช้ เช่น หาทัวร์ที่กำลังแข่งแล้วเปิดดูสาย
3. จุดที่เปลี่ยนจากรอบก่อน และสิ่งที่อยากให้เน้น
4. สิ่งที่ล็อกไว้ เช่น สีแบรนด์ ฟอนต์ ขอบเขต API และเวลาพัฒนา
5. ต้องการรีวิวอย่างเดียวหรือให้แก้แบบด้วย การขอรีวิวไม่ใช่คำสั่งให้แก้ไฟล์หรือโพสต์คอมเมนต์แทนผู้ใช้

ตัวอย่างข้อความที่ใช้ได้ทันที:

> รีวิว Figma The Ranking ทั้ง 3 หน้า ทั้ง desktop/mobile แบบตรง ๆ เป้าหมายคือให้ผู้ชมหาทัวร์ที่กำลังแข่ง เปิดสาย และอ่านผลได้เร็ว ช่วยตรวจ flow, ลำดับข้อมูล, ภาษาไทย, ฟอนต์ IBM Plex Sans Thai, responsive และความเป็นไปได้กับ API เดิม จัดลำดับ P1/P2/P3 พร้อมลิงก์ frame และข้อเสนอแก้ไข ขอรีวิวอย่างเดียวก่อน

## ลำดับการรีวิว

1. **Flow และข้อมูล:** คนดูหางานหลักเจอหรือไม่ แต่ละสถานะมีข้อมูล/ปุ่มถูกต้องหรือไม่ และชื่อสถานะตรงกับ backend หรือไม่
2. **Hierarchy และการอ่าน:** หน้าหลักนำไปสิ่งที่คนดูต้องการ ชื่อทีม คะแนน เวลา และปุ่มหลักเด่นพอโดยไม่แข่งกันทั้งหน้า
3. **มือถือและกรณีขอบ:** ชื่อยาว ทีมจำนวนมาก ไม่มีรูป ไม่มีสาย มีทั้งสายบน/ล่าง ข้อมูลว่าง และหน้าจอช่วง 768 พิกเซล
4. **Typography และการเข้าถึง:** สระ/วรรณยุกต์ ขนาดตัวอักษร contrast การใช้สีร่วมข้อความ และ focus/keyboard behavior ที่ต้อง implement
5. **ความพร้อมส่งต่อ:** ใช้ components/tokens จริง ไม่มีข้อมูลสำคัญถูก clip และ prototype มีความหมายตรงกับโค้ดที่จะทำ

ฟอนต์ในหน้า canvas เป็นผลที่ต้องดูร่วมกับ styles ไม่ใช้แค่ชื่อ style เป็นหลักฐานว่าไม่มี overrides และอย่าแก้ layout ให้ดูพอดีด้วยการลดขนาดตัวอักษรจนอ่านยาก

## รูปแบบผลรีวิว

แต่ละ finding ควรมี:

- **ระดับ:** P1 ขวาง flow/ทำให้ข้อมูลผิดหรือหาย, P2 สร้างความสับสนหรือใช้งานยาก, P3 งานเก็บรายละเอียด
- **ตำแหน่ง:** ลิงก์ frame/ส่วนที่ตรวจ พร้อมบอก desktop หรือ mobile
- **สิ่งที่เห็น:** ข้อเท็จจริงที่ตรวจได้จากแบบล่าสุด
- **ผลต่อผู้ใช้:** ทำให้งานใดช้าลง ผิด หรือทำไม่ได้
- **ข้อเสนอ:** แนวแก้ที่สอดคล้องกับ sprint และระบบเดิม
- **เกณฑ์ตรวจซ้ำ:** สิ่งที่ต้องเห็นจึงถือว่าปิด finding

แยก finding ที่มีหลักฐานออกจากความชอบส่วนบุคคล ไม่เรียกรูปแบบว่าใช้ได้หรือใช้ไม่ได้โดยไม่อธิบายผลต่อผู้ใช้ และไม่อ้างว่าผ่าน usability testing ถ้ายังไม่มีการทดสอบกับผู้ใช้จริง
